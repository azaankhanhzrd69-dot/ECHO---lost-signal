## Findings (pre-write report)

### 1. AlertMeter — real public API
```csharp
// namespace Echo.Core  — one UnityEngine using (Mathf + Vector3 only)
public class AlertMeter
{
    public float Value { get; private set; }
    public void  Configure(float hearingRadius, float gainScale, float decayPerSecond)
    public float Add(Vector3 noiseWorldPos, float loudness, Vector3 monsterWorldPos)
    public void  Tick(float deltaTime)
    public void  Reset()
    public bool  IsAbove(float threshold)  // >= threshold
}
// Formula: effective = Max(0, loudness * (1 − dist/hearingRadius)) * gainScale
//          Value += effective
//          Tick: Value = Max(0, Value − decayPerSecond * deltaTime)
// Zero radius guard: if (_hearingRadius <= 0f) return 0f;
```
Matches the intended design exactly. No changes to production code needed.

### 2. HideRules — real public API
```csharp
// namespace Echo.Core — zero UnityEngine dependency
public enum HideOutcome { InstantKill, Normal, ForcedDeath }
public static class HideRules
{
    public static HideOutcome Evaluate(
        HideKind kind, bool isIntro, int safeHidesSoFar, int safeHidesBeforeDeath)
}
// Table/Chair → InstantKill (any context)
// Locker + isIntro        → Normal (does not count toward limit)
// Locker + !isIntro + safeHidesSoFar <  limit → Normal
// Locker + !isIntro + safeHidesSoFar >= limit → ForcedDeath
```
Story rule "4th hide kills" verified: with default limit=3, safeHidesSoFar=3 → ForcedDeath. ✅

## Gameplay Fixes (delivered in same session)

### Fix 1 — Noise Bar (Player-Facing HUD)
**File:** `Assets/ECHO/Scripts/Core/Noise/PlayerNoiseUI.cs`

- `OnEnable` subscribes to `EchoEvents.Noise`; `OnDisable` unsubscribes.
- Each noise event spikes the bar to `Max(currentLevel, loudness)`.
- Bar decays back to zero over `fadeTime` seconds (default 1.5 s) in `Update`.
- Drives `Slider.value` **or** `Image.fillAmount` — assign one in the Inspector.
- No TextMeshPro, no Find, no `Update` polling when idle.

### Fix 2 — Monster "Sight" (code review result)
After reviewing `MonsterAI.Update()` and `TickStateMachine()`:

- The monster navigates **only** to `_lastHeardPosition` (set from `EchoEvents.Noise`). It never reads `playerTransform.position` for navigation.
- `playerTransform` is used only for the **kill-range distance check** (`tuning.killRange`). This is correct: the monster kills you when it physically reaches you within 1.45 m, not because it "sees" you.
- While `_isScripted == true`, `MonsterAI.Update()` returns at the top guard (`if (tuning == null || _isScripted) return`), so the kill check is also skipped during sequences and hiding.
- **Conclusion:** No sight-based detection exists. The perceived "seeing" is because `PlayerNoiseEmitter` fires noise every footstep, making `_lastHeardPosition` track the player accurately. This is by design.
- **No production change was needed for Fix 2.**
